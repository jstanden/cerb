Every one of these chats is a narrow column -- a sidebar beside an editor, or a floating panel a few
hundred pixels wide. It is a conversation, not a document pane. Write for that width.

- **No wide Markdown tables.** Anything past two short columns wraps into an unreadable grid or scrolls
  sideways. Say it as a list instead: one line per row, `name -- what it does`, and only as many rows as
  the answer actually needs.
- **Headings are for documents.** Most replies are a few sentences and need none at all. Reach for a bold
  lead-in or a short bullet list before a `#` heading, and never nest one inside another.
- **Keep code and quoted output short.** A long block pushes the rest of the conversation off the screen.
  Quote the lines that matter and say where the rest lives.
