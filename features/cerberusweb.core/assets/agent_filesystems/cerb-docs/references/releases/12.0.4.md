**Cerb (12.0.4)** is a **maintenance update** released on November 19, 2026. It includes **26** minor features, fixes, and security patches from community feedback covering the [12.0](/releases/12.0/) update. You can [follow these instructions](/docs/upgrading/) to upgrade.

# Changelog

## Changed

- **[Dashboards/Widgets]** Widgets authored by administrators now show stats across all groups to everyone who can view them, instead of only the viewer's groups. This includes profile and card widgets, and workspace widgets on pages owned by the app or an administrator. Records listed in these widgets are still filtered for the viewer. Cached data query results are also no longer shared between workers who can see different groups.

- **[Data Queries]** The `ids:` parameter in `usage.snippets` and `usage.behaviors` data queries (`format:timeseries`) now only accepts numeric IDs.

- **[Tasks/Projects]** Task projects now only organize tasks and no longer restrict access to them. All workers can read tasks and projects, and updating or deleting a task follows the worker's role privileges.

- **[Mail/Forward]** Forward drafts now store the original message's attachments in their file attachments when created, instead of the reply form adding them every time it opens. Drafts created by automations with `ticket.forward` only include the attachments they're given, and removing every attachment from a forward draft now sticks.

## Fixed

- **[Custom Fields/Files]** Fixed setting a file custom field on one record removing the file links for other records using the same field. Those files could become undownloadable through the field, or be purged as unattached files during maintenance. Removing a file from one record also no longer unlinks it from other records that still hold it.

- **[Data Queries]** Fixed cached data query results being shared between different records or dashboard prompt values. Widgets with a cache time that use `${placeholders}` (such as card and profile widgets, or dashboards with prompts) could show results meant for another record or another worker's prompt selections.

- **[Contacts]** Fixed the 'new contact' popup failing to open.

- **[Worklists/Subtotals]** Fixed an issue with adding filters from group and bucket subtotals on message worklists.

## Security

- **[Security/Worklists]** Fixed bulk updates being able to put any file into a file custom field, which granted download access to attachments the worker couldn't otherwise see. Bulk updates now only accept files the worker can download. Thanks to wranked.1 for the report!

- **[Security/Data Queries]** `attachment.manifest` data queries now only list the contents of ZIP files the active worker can download. Thanks to wranked.1 for the report!

- **[Security/Data Queries]** Fixed `worklist.subtotals`, `worklist.series`, `worklist.xy`, `worklist.geo.points`, and `worklist.metrics` data queries including tickets and messages in private groups the active worker isn't a member of. This follows the earlier `worklist.records` fix. Thanks to wranked.1 for the report!

- **[Security/Worklists]** Ticket and message worklists now always exclude private groups the worker isn't a member of. Previously, a search like `group.id:` could override the default group filter and list tickets from those groups. This also applies to worklist subtotals, exports, bulk updates, and automations running in a worker's session. Thanks to wranked.1 for the report!

- **[Security/Support Center]** Message content links in the Support Center ticket history are now limited to web URLs.

- **[Security/Mail]** Fixed header values on messages created by Cerb (such as Support Center contact form submissions) being able to add extra message headers. Thanks to Omar Ahmed Abdelsalam Elsayed for the report!

- **[Security/Support Center]** The contact form confirmation now only shows a reference number for newly created tickets. Thanks to Omar Ahmed Abdelsalam Elsayed for the report!

- **[Security/Comments]** Comments are now only readable by workers who can read the commented record (e.g. private group tickets), including in the REST API. Thanks to Adarify Group for the report!

- **[Security/Drafts]** Ticket reply and forward drafts are now only readable by workers who can read the ticket. Thanks to Adarify Group for the report!

- **[Security/Worklists]** Comment and draft worklists now hide the content of rows the current worker can't read, while keeping them in the counts.

- **[Security/Calendars]** Calendar events from worklist series now only include records the current worker can read. This prevents comments and drafts on private group tickets from appearing in calendar widgets and `calendar.events` data queries.

- **[Security/Worklists]** Sorting worklists by custom fields now strictly validates the sort field. Thanks to Omar Ahmed Abdelsalam Elsayed for the report!

- **[Security/Login]** Failed multi-factor authentication codes are now logged and count toward the temporary account lockout across logins. Thanks to kta1kri for the report!

- **[Security/Bots]** Only administrators can create, import, or modify behaviors on bots owned by a role, since those behaviors run with administrator privileges. Thanks to Romel Lanza for the report!

- **[Security/Search]** Search filters from the API, worklists, and saved worklist models are now more strictly validated. Thanks to Omar Ahmed Abdelsalam Elsayed for the report!

- **[Security/Worklists]** Worklist filter descriptions are now consistently HTML-escaped.

- **[Security/Mail]** Reply and forward drafts are no longer created for tickets the worker can't reply to. Previously, a denied reply could still save a draft quoting the message. Thanks to Yannael for the report!

- **[Security/Snippets]** Pasting a snippet now requires permission to read it. Previously, a worker could paste another worker's private snippet by its ID. Thanks to wranked.1 for the report!
